# Security & Privacy

infernoflow stores AI session memory locally as plain JSONL files. This document is a transparent description of what the tool does on your machine, what (if anything) it sends over the network, and how to report security issues.

## What infernoflow writes to disk

When you run `infernoflow init` or `infernoflow log`, the tool writes plain text/JSON files in your project:

- `.ai-memory/sessions.jsonl` — one entry per line, each ~200 bytes. AMP-format JSON. Holds the gotchas/decisions/attempts you've logged.
- `.ai-memory/amp.json` — project metadata (name, AMP version, simple config).
- `.ai-memory/handoff.md` — generated by `infernoflow switch`. A markdown handoff for AI agents.
- `.cursorrules`, `CLAUDE.md`, `.github/copilot-instructions.md` — auto-injected sections wrapped in `<!-- infernoflow:start -->` / `<!-- infernoflow:end -->` comment markers. Your manual edits outside those markers are never touched.

The tool never writes outside the project directory it's run from, except for one optional case (cloud sync, below). It never modifies system files, registry entries, or `~/.bashrc` / `~/.profile`.

## What infernoflow runs at install time

**Nothing.** As of v0.43.5, the npm package has no `postinstall` script. `npm install -g infernoflow` only copies files into `node_modules` — no code executes.

## What infernoflow sends over the network

By default, **nothing.** The CLI is fully local. Two opt-in features can send data:

### 1. Cloud sync (`infernoflow login`)

If you opt in by running `infernoflow login`, the CLI uses GitHub Device Flow to identify you, then mirrors your `sessions.jsonl` entries to a hosted Supabase project. This is **off by default** and requires explicit consent.

**Current limitation (v0.43.x):** the cloud sync uses an anonymous Supabase key with per-user tokens. Any leaked anon key would let an attacker write rows. **For sensitive projects, do not run `infernoflow login`.** A proper authenticated mode (OAuth/JWT scoped per user) is on the roadmap; the schema is already forward-compatible (`scripts/supabase-schema.sql`).

### 2. AI provider commands (`infernoflow ai setup`, `infernoflow explain`, etc.)

If you configure an AI provider via `infernoflow ai setup`, certain commands send your code/context to that provider (Anthropic, OpenAI, Google, OpenRouter, or local Ollama). Same trust model as using the provider directly. Off by default — you must explicitly run `infernoflow ai setup`.

### 3. MCP server (`infernoflow setup`)

The MCP server (`templates/cursor/inferno-mcp-server.mjs`) runs locally as a subprocess of your AI tool (Cursor / Claude Code / etc.). It only invokes the local `infernoflow` CLI — no direct network calls. Your AI tool's own network behavior is unchanged.

## What infernoflow does NOT do

- **No telemetry.** No analytics, no error reporting, no install-tracking pings.
- **No auto-updates.** The CLI never modifies itself; updates only via `npm install -g infernoflow@latest`.
- **No background processes.** Nothing daemonizes; commands exit when done. The optional `infernoflow watch` runs in your terminal foreground only.
- **No reading of files outside your project.** Glob patterns are scoped to the working directory.
- **No secret detection / extraction.** The MCP server has a `containsSecret` check that *prevents* writing secrets into memory — but doesn't scan or transmit anything else.

## Reporting security issues

If you find a vulnerability, please report it privately:

- Email: hello@infernoflow.dev
- Or open a GitHub Security Advisory: https://github.com/ronmiz/infernoflow/security/advisories/new

Please don't open a public issue for security bugs. We'll acknowledge within 72 hours and aim for a patched release within 7 days for actively exploitable issues.

## Honest disclosure

infernoflow is in active development. The cloud sync auth model is genuinely weak right now — we're disclosing this here rather than burying it. If your threat model includes "another developer with the public anon key writing rows to my cloud history," **don't enable cloud sync until v0.44 ships proper auth.** Local-only mode is unaffected and is what most users should run.
