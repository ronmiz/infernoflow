🧠 המהות של המוצר — בשורה אחת

infernoflow היא זיכרון מתמשך לצוות של human+AI שעובד ביחד על פרויקט קוד. המוצר תופס את הידע הלא-מקומי (gotchas, decisions, attempts, patterns, bookmarks) שקיים במפגש כרגע — ומזריק אותו לsession הבא. אין SaaS, אין vendor lock-in, JSONL על הדיסק, MCP server, ו־3 rule files שכל IDE כבר קורא.

הכאב שהיא פותרת בפועל (בדוגמאות מ־dogfood-infernotest_01.md)

  • "Vite proxy עם changeOrigin משנה Host header" — שעה של דיבוג לפני שהבחין. נלכד → סessions הבאים מוזהרים מראש.
  • "Prisma 6 DLL נעולה בזמן tsx watch" — הודעת EPERM מטעה. נלכד כ־gotcha, פותר עתידית.
  • "invite accept שורף token גם אם המשתמש כבר חבר" — bug שדורש 2 משתמשים לשחזור. נלכד → תיקון מיידי.
  • "npm install מסיר בשקט npm link" — bug מדרגה שנייה שגרם ל־wrapper ישן להיטען. תיקון: 0.44.0 מכניס AMP IO in-process.
  • "עריכת MCP server file לא עושה hot-reload" — הפך ל־feature: boot stamp ב־.mcp-runtime.json.

🔖 Feature Deep-Dive: infernoflow bookmark (v0.44.10 — הכותרת)

מה זה: Bookmark = note tagged bookmark — resume point עם label וקונטקסט. המידע הרחב יורד לTier-2 detail sidecar (.ai-memory/details/<id>.md) כדי שלא ינפח את ה־index העצום שנטען בכל session.

🎯 3 מסלולי הפעלה (הכל מתכנס לאותו storage)

🖥️ מסלול 1 — CLI ידני
infernoflow bookmark "before the SP refactor"
+ אופציות: --note --detail-file <path|-> --marker --tags
↓
🤖 מסלול 2 — AI דרך MCP
AI קורא ל־amp_bookmark({label, note?})
מבוקש ע"י ה־AI כאשר: המשתמש אומר "bookmark this" / לפני שינוי מסוכן / context window מתמלא
↓
🪝 מסלול 3 — Deterministic Cursor Hook
beforeSubmitPrompt חוטף את הפרומפט וסורק ב־regex לפני שהוא נשלח:
/\bbookmark (?:this|it|here)(?: point)?\b/i
/\bmark this (?:point|spot|moment|here)\b/i
/\bsave (?:this )?(?:point|checkpoint|resume point)\b/i
✓ עובד גם אם ה־AI לא משתף פעולה. Trigger זה גובר על ה־trouble triggers (!!, retry, וכו').
↓
💾 Storage & Auto-Capture
1. יוצר entry ב־.ai-memory/branches/<branch>.jsonl
2. אם לא ניתן --note/--marker → קורא ל־harvestSnapshot(cwd) ← מחלץ אוטומטית את ה־Claude Code transcript (40 turns אחרונים, 1500 chars per turn)
3. שומר את הקונטקסט ב־.ai-memory/details/<id>.md

🔍 ה־harvestSnapshot — הקסם הטכני מאחורי הauto-capture

הפתרון החכם: Claude Code כבר כותב את כל השיחה ל־~/.claude/projects/<encoded-cwd>/*.jsonl. הקידוד: absolute path → מוחלף כל תו לא-אלפאנומרי ב־"-". infernoflow פשוט קורא את הקובץ הזה, מחלץ את 40 ה־turns האחרונים, ומאחסן כ־markdown snapshot. אין קריאה למודל. אין תלות בAI. deterministic 100%.

🎯 Sub-commands

פקודהשם חלופימה עושה
bookmark "<label>"—יוצר bookmark (default action)
bookmark listlsרשימת כל ה־bookmarks. ● = יש context, ○ = marker בלבד
bookmark show <id|label>jump, recallמציג bookmark ספציפי + הקונטקסט שלו
bookmark rm <id|label>remove, deleteמוחק bookmark

🎯 Resolver Algorithm (איך show ו־rm מוצאים את הבוקמארק)

  1. ID exact match → מנצח
  2. ID prefix match (למשל show 01HP3K) → אם יש אחד, מנצח
  3. Label substring, case-insensitive → אם יש אחד, מנצח
  4. אם יש כמה labels שמתאימים → ה־newest מנצח (עם הודעת אזהרה שיש עוד)
  5. ID prefix ambiguous → error, מבקש לפרט

🚨 Design decisions חשובות

  • Bookmarks are NEVER auto-pruned (PROTECTED handling ב־amp/io.mjs) — בניגוד לnotes/attempts/detections שמתפוגגים אחרי 30 יום.
  • Two-tier storage — ה־detail הרחב לא נטען כשה־AI קורא את המidx הרגיל. רק בקריאה ל־readDetail().
  • Trigger deduplication — hash של 200 תווים ראשונים של הפרומפט נשמר ב־.trigger-state.json. אותו prompt לא יוצר bookmark כפול.
  • Label derivation — הhook מסיר את הפרזה טריגר ומשתמש ב־80 התווים הראשונים כ־label. אם ריק → "Session bookmark".
  • Agent detection — env vars: CURSOR_SESSION / COPILOT_SESSION / CLAUDE_CODE_SESSION / WINDSURF_SESSION / INFERNOFLOW_AGENT.
  • Bookmarks מופיעים בhandoff — switch יוצר ## 🔖 Bookmarks — Resume Points. ה־context של ה־newest נכנס inline בתוך <details> כדי לא לנפח.

🎯 Positioning Insights שלמדתי מ־BLOG_POST.md

יש לך 3 קטגוריות של ידע שה־AI לא רואה:
  1. Things you tried that didn't work — "ניסיתי react-query, חזרתי לcustom hook". מחר ה־AI מציע react-query שוב.

הזווית הפילוסופית (AMP as protocol): "אם רק הכלי שלי יכול לקרוא את הזיכרון שלי, בניתי את הNotion של AI. AMP הוא הrelease valve — spec פתוח, JSONL, כל אחד יכול לממש. הצד השני של lock-in נעלם ברגע שיותר מכלי אחד מיישם אותו."
Metaphor מנצח: "AMP is to AI coding assistants what .gitignore is to version control."
